# 3 分钟演示脚本

目标：非技术听众 30 秒理解主线，技术面试官在剩余时间内下钻证据链。

## 0:00–0:30 定位（冻结案例首页）

打开 `http://<demo>/`，默认就是冻结黄金案例。

> “AI 在电商规则里搜索异常操作组合——不是检查单条规则，而是搜索组合拳。
> 每个候选都要通过真实 API 重放，由确定性 Oracle 裁决，不是模型说了算。”

指出页面标语：**AI 搜索电商规则的异常操作组合，真实 API 重放，确定性 Oracle 裁决。**

## 0:30–1:10 规则与运行（滚动到证据）

- 自然语言规则：“每消费 1 元获得 1 积分，退款时按退款金额撤销积分。”
- 旁边是冻结的 RuleSpec JSON：编译后不可变，content hash 绑定。
- 最小反例 4 步：创建用户 → 下单 100 元 → 支付 → 退款 50 元。
- 每步的 State Diff 来自真实 Sandbox 快照：退款 50 元，积分余额不减反增。

## 1:10–1:50 证据链下钻（技术面试官）

- 回执（Receipt）与领域事件来自真实 HTTP 重放，可追溯 replay run id。
- 重放稳定性 3/3：独立干净 RunSpace 中三次重放同一违反。
- 技术模式展开 Trace：模型配置 hash、工具调用、延迟、成本。
- 强调：Agent 只有结构化提议权；确认仅来自 Oracle。

## 1:50–2:20 修复回归

- 同一反例在 Fixed v2 重放：不再违规（页面徽章“旧反例不再成立”）。
- 正常部分退款仍然通过——不是靠删功能修漏洞。

## 2:20–3:00 实时运行与边界

- 切到“实时运行”：选模板、输入中文规则、确认歧义、启动。
- 预算上限：12 步 / 12k tokens / $1.5 / 90 秒；超限即停。
- 诚实语义：“预算内未发现违规”≠“安全”；基础设施工失败与业务结论分离。
- 若模型不可用：页面显示真实失败状态，冻结案例不受影响。

## 收尾一句话

> “多策略 Agent 的价值不在于更聪明，而在于在确定性边界内更快找到反例；
> 所有结论都能追溯到一次真实重放。”
