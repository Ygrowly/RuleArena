# 3 分钟演示脚本

目标：非技术听众 30 秒理解主线，技术面试官在剩余时间内下钻证据链。

打开方式二选一：

- **单文件**：双击 `frontend/dist-standalone/rulearena-demo.html`（无需 Docker / 后端 / 模型）
- **完整栈**：`docker compose up -d --build` → `http://127.0.0.1:8080`

## 0:00–0:30 定位（冻结案例首页）

默认打开的就是冻结黄金案例——一次**真实完成**的运行快照。

> “AI 在电商规则里搜索异常操作组合——不是检查单条规则，而是搜索组合拳。
> 每个候选都要通过真实 HTTP API 重放，由确定性 Oracle 裁决，不是模型说了算。”

指出页面标语：**AI 搜索电商规则的异常操作组合，真实 API 重放，确定性 Oracle 裁决。**

## 0:30–1:10 结论先行（页面顶部）

页面第一屏直接给结论：**“模型在 4 步内搜索到一条可复现的积分价值守恒违规”**，
下面是四条支撑事实（真实 HTTP 重放 / Oracle 判定 / 独立重放 3/3 / 修复版不复现），
再往下才是细节。

再指出最下面那行 `provenance.honesty`：**路径由谁提出、裁决由谁做出，写在页面上。**
（这一版是真实模型 `deepseek-v4.1-flash` 提出的；旧版本是脚本给出的，页面会如实改口径。）

## 1:10–1:50 反例与证据链（技术面试官）

- 自然语言规则：“每消费 1 元获得 1 积分，退款时按退款金额撤销积分。”
- 模型给出的 4 步路径：创建用户 → 下单 200 元 → 支付 → 全额退款 200 元。
- **红框那一步是违规发生处**：用户拿回 200 元退款，**积分却从 200 变成 400**——
  退款本该撤销积分，实测不降反增。三个数字（余额 300→500、积分 200→400、
  累计退款 0→200）都是真实 Sandbox 快照的 Diff，不是模型叙述。
- 上方蓝色引用块是 **Oracle 自己的裁决原文**，不是界面的转述。
- 回执（Receipt）与领域事件来自真实 HTTP 重放，可追溯 replay run id。
- 重放稳定性 3/3：独立干净 RunSpace 中三次重放同一违反。
- 技术 Trace 展开：8 次真实模型调用，含 input/output tokens、延迟与成本。
- 强调：Agent 只有结构化提议权，不能自封结论；确认仅来自 Oracle。

## 1:50–2:20 修复回归

- 同一反例在 Fixed v2 重放：不再违规（页面徽章“旧反例不再成立”）。
- 正常退款路径仍然通过——不是靠删功能修漏洞。

## 2:20–3:00 实时运行与边界

- 切到“实时运行”：选模板、输入中文规则、确认歧义、启动。
- 预算上限写在页面上；超限即停，不伪装成结论。
- 诚实语义：“预算内未发现违规”**≠**“安全”；基础设施失败与业务结论分离。
- 若模型不可用：页面显示真实失败状态，冻结案例不受影响。

## 技术面试官追问时的评测数字（golden-v3 + 全部修复后）

- 四基线 dev：RANDOM 0/9、BFS 2/9、SINGLE 0/9、**MULTI 2/9**。
- **LLM 与 BFS 持平，且 95% Wilson 区间重叠**（0/9 是 [0,30%]，2/9 是 [6,55%]），
  所以正确说法是“当前样本量无法区分”，不是“谁更强”。要让 `0/n` 的上界低于 22%
  需要 **n ≥ 14** 个漏洞 case，当前 9 个。
- 机制层：候选确认 4/34、独立重放 **12/12**、误报 0/7、泄漏 0。
- 一处如实降级：仍有 2 个 case 的路径只违反了**别的**不变量而非标注的那条，
  这暴露的是靶场设计（多个 case 共用同一缺陷环境），已记为下一步要修的问题。

## 收尾一句话

> “多策略 Agent 的价值不在于更聪明，而在于在确定性边界内更快找到反例；
> 所有结论都能追溯到一次真实重放——包括对我不利的那些结论。”
